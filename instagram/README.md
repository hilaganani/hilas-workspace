# Instagram — Knowledge Index

זהו קובץ הכניסה לכל משימת Instagram. הוא ממפה את מקורות האמת ואינו מחליף אותם.

## סדר קריאה מחייב

לפני תכנון, שינוי לוח, כתיבה, ניתוח ביצועים או המלצה:

1. `instagram/current-state.md`
2. `instagram/master-brief.md`
3. `instagram/content-pillars.md`
4. `instagram/content-bank.md`
5. `instagram/highlights.md`
6. `instagram/measurement.md`
7. `instagram/learning-log.md`
8. מסמך ההשקה שאליו מפנה `current-state.md`, אם יש השקה פעילה
9. snapshot עובדתי עדכני מ-Instagram Ops, המבוסס על Google Sheet ועל Evidence חי זמין

אין להסתמך על thread קודם, תאריך יעד כהוכחת פרסום, working tree אחר, `yael/` או `output/` כדי לשחזר את מצב Instagram הפעיל.

## קדימות במקרה של סתירה

אין מקור יחיד שגובר בכל סוגי המידע:

1. נוסח, Hook, מבנה, מטרה, CTA ומיצוב: מקורות Git המאושרים גוברים.
2. מחיר, הצעה ותאריכי השקה: מסמך ההשקה המלא גובר.
3. האם משהו פורסם: Evidence חי גובר על Sheet ועל Git.
4. לאחר אימות, ה-Sheet מחזיק סטטוס, קישור ומועד תפעוליים; `current-state.md` מחזיק את ה-handoff והפעולה הבאה.
5. לקח אסטרטגי קיים רק לאחר שנשמר ב-`learning-log.md` על בסיס Evidence.
6. סתירה לא פתורה אינה מוכרעת אוטומטית: מסמנים `conflict`, שומרים את שני הצדדים ואוספים Evidence לפני שינוי.

לזיהוי רשומה משווים לפחות `Content ID + כותרת + פורמט`. התאמה של ID בלבד אינה מספיקה.

## מה נמצא מחוץ ל-Git

- Google Sheet מחזיק מצב תפעולי ונתוני ביצועים גולמיים.
- Instagram והקישורים החיים הם Evidence לפרסום בפועל.
- נכסי עיצוב, סרטונים וקובצי הפקה יכולים להישמר במקום העבודה הרגיל ואינם מקור אמת תוכני.
- `yael/` ו-`output/` אינם מקורות אמת של תוכנית Instagram שלאחר ה-reset.

אם חיבור חיצוני אינו זמין, מדווחים את הפער ולא משלימים את המידע מהשערה.

## סגירת אירוע

אירוע או החלטה אינם יכולים להישאר רק בשיחה. בסיום אירוע פועלים כך:

`Evidence → אימות סמכות → עדכון המקור המתאים → קריאה חוזרת → עדכון current-state כשהמצב או הפעולה הבאה השתנו`

קריאה ואימות יכולים להתבצע אוטומטית. שינוי תוכן, החלטה אסטרטגית או שינוי במערכת חיצונית נעשים רק במסגרת הסמכות שהוגדרה או לאחר אישור מפורש.
