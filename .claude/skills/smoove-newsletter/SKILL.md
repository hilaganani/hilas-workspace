# smoove-newsletter — טיוטת קמפיין בסמוב (לא שולח)

## מטרה והיקף — גבול מכוון, לא זמני

הסקיל הזה **יוצר טיוטה בלבד**. הוא **לעולם לא** קורא ל-endpoint השליחה של סמוב (`POST /v1/Campaigns/{id}/Send`), ואסור להוסיף קריאה כזו — זו לא מגבלה טכנית שתיפתר בעתיד, זו החלטה מכוונת: לחיצת "שלח" נשארת תמיד ביד של המשתמשת בממשק סמוב עצמו. זה גם מה שמאפשר לתת לנגה גישת API מצומצמת בלי לפרוץ את הכלל הקיים שהיא לא שולחת שום דבר בעצמה.

## מתי להשתמש

אחרי שנגה סיימה לכתוב ניוזלטר (יש `<name>.html` ב-`output/`), ורועי מחליט שהוא מוכן ליצור ממנו טיוטה בסמוב.

## הקדמה: הקמה חד-פעמית

1. בסמוב: hover על שם החשבון → **API Keys & pixels** → **Add API Key**. תני לו הרשאה שמאפשרת יצירת קמפיינים (לא Read Only). שמרי את המפתח.
2. הריצי `python3 ${CLAUDE_SKILL_DIR}/scripts/create_draft.py list-lists` כדי לראות את רשימת ה-Lists שלך והמזהה המספרי (`id`) של הרשימה שאליה הניוזלטר אמור להישלח.
3. הוסיפי ל-`.env`:
   ```
   SMOOVE_API_KEY=your_smoove_api_key_here
   SMOOVE_LIST_ID=the_numeric_list_id_here
   ```
4. `pip3 install requests` אם עוד לא מותקן.

## קלט נדרש

| שדה | חובה/רשות |
|---|---|
| נתיב לקובץ `.html` מוכן (מ-`output/`) | חובה |
| נושא המייל (Subject) | חובה |

## תהליך עבודה

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/create_draft.py create-draft \
  --subject "<נושא הניוזלטר>" \
  --html-file output/<name>.html
```

הפלט כולל את מזהה הקמפיין שנוצר (`id`) ופרטיו. **דווחו למשתמשת**: "טיוטת ניוזלטר נוצרה בסמוב (קמפיין #<id>) - לפתוח בממשק סמוב תחת Campaigns, לבדוק, וללחוץ שלח כשמוכנה." לעולם לא לדווח "הניוזלטר נשלח" - זה לא נכון, זו רק טיוטה.

**חשוב**: הטיוטה נפתחת בממשק סמוב במצב **"עורך HTML"** (גולמי), לא במצב עיצוב/תבנית ויזואלי - ראו "מגבלה ידועה" למטה. אם המשתמשת רגילה לעבוד עם תבנית עיצוב משלה, זה שלב ידני נוסף מצדה (להעתיק את התוכן לתבנית), לא משהו שהסקיל פותר.

## מגבלה ידועה: אין תמיכה אמיתית בתבנית עיצוב ויזואלית

נבדק בפועל (2026-07-14): גם עם `--template-name`/`SMOOVE_TEMPLATE_ID` מוגדר לערך `templateId` תקין (מ-`list-templates`), הקמפיין שנוצר עדיין נפתח בסמוב במצב **"עורך HTML"**, לא במצב "Studio Editor" (התבנית הוויזואלית שהמשתמשת בדרך כלל בוחרת ידנית). כלומר `POST /v1/Campaigns` עם `body` גולמי לא מפעיל את עורך העיצוב הוויזואלי, גם עם `templateId` - זו כנראה מגבלה אמיתית של ה-API הזה (עורך העיצוב הוויזואלי נגיש רק דרך הממשק), לא טעות בפרמטר. **אל תנסו שוב קומבינציות פרמטרים נוספות בלי סיבה קונקרטית חדשה** - זה נבדק שלוש פעמים (`templateName` עם ID, `templateName` עם שם, `templateId` עם ID) ולא השיג את האפקט הרצוי באף אחת מהן. הפרמטר `--template-name` נשאר בסקריפט (לא מזיק, לא גורם לשגיאה) אבל לא פותר את בעיית עורך ה-HTML הגולמי.

**המשמעות בפועל**: הטיוטה שהסקיל יוצר תמיד תהיה HTML גולמי. אם המשתמשת רוצה את זה בתבנית העיצוב שלה - זה שלב ידני שהיא עושה בעצמה בסמוב (להעתיק את התוכן לתוך התבנית), לא משהו שהסקיל אוטומטי לגביו.

## אין שדה API לטקסט תצוגה מקדימה (preview text / preheader)

נבדק מול סכמת הבקשה המלאה (2026-07-14) - **אין שדה כזה** ב-`CreateCampaignRequest`. הדרך המקובלת ליצור טקסט תצוגה מקדימה היא הטמעת קטע טקסט מוסתר בתחילת ה-`<body>` של ה-HTML עצמו (למשל `<div style="display:none">...</div>`) - זה שינוי בתוכן ה-HTML שנגה כותבת, לא פרמטר בסקיל הזה. לא אומת אם זה בפועל מוצג נכון בתיבת דואר - צריך בדיקה ידנית בתצוגה מקדימה של קמפיין בסמוב.

## ולידציה ומקרי קצה

- **פורמט ההזדהות ושדות הבקשה אומתו** (2026-07-14) מול קריאה אמיתית עם מפתח פעיל — `Authorization: <המפתח עצמו>` (בלי `Bearer`) ו-`subject`/`body`/`toListsById`/`trackLinks` עובדים כמו שהם. אם עדיין מתקבלת שגיאת `401`/validation בעתיד (למשל אחרי שינוי ב-API של סמוב), פתחו את `rest.smoove.io` ובדקו את הסכמה העדכנית ישירות (הוכח אמין יותר מסיכום אוטומטי של הדף - ה-templateName/templateId לעיל התגלה דרך בדיקה ידנית של המשתמשת בממשק Swagger האמיתי, אחרי שסיכום אוטומטי נתן שם פרמטר שגוי).
- **`contactsCount` בתשובת `list-lists` מציג `0` לכל הרשימות**, כולל רשימות שבוודאות יש בהן אנשי קשר — נראה שדה לא אמין בתגובת ה-API הזו, לא סימן שהרשימה ריקה. אל תסיקו מכך שרשימה ריקה בפועל.
- **`SMOOVE_LIST_ID` לא מוגדר** — הריצו `list-lists` תחילה, אל תנחשו מזהה.
- **קובץ ה-HTML מכיל CSS מוטבע כבד** — זה תקין, נגה כבר כותבת HTML עם `<style>` מוטבע; ודאו רק שהקובץ שלם ותקין (לא truncated).

## שילוב עם נגה

נגה **לא** מפעילה את הסקיל הזה בעצמה בזמן הכתיבה — היא רק כותבת וכותרת ל-`output/`. הפעלת הסקיל (יצירת הטיוטה בסמוב) קורית בשלב נפרד, אחרי שרועי מקבל את הדוח שלה ומחליט להריץ אותו. נגה מדווחת רק שהקובץ מוכן, לא יוצרת את הטיוטה כחלק אוטומטי מתהליך הכתיבה.
