# html-to-pdf — תצוגה מקדימה ויזואלית ל-Google Drive

## מטרה והיקף

Google Drive אף פעם לא מרנדר קובצי `.html` בתצוגה המקדימה שלו - הוא תמיד מציג אותם כטקסט/קוד גולמי, מטעמי אבטחה (מניעת הרצת קוד זדוני). זו התנהגות קבועה של גוגל, לא ניתנת לשינוי מצד ההעלאה עצמה. הסקיל הזה עוקף את זה: מרנדר את ה-HTML ל-PDF (ש-Drive כן יודע להציג ויזואלית בתצוגה מקדימה, בכל מחשב, בלי הורדה), ומעלים את שניהם - ה-HTML המקורי (לעריכה/שימוש בפועל) וה-PDF (לצפייה מהירה).

## ברירת מחדל בפרויקט

כל ניוזלטר שמופק (על ידי נגה, ומשולב על ידי רועי) מרונדר ל-PDF, **וה-PDF הוא הקובץ היחיד שעולה ל-Drive**. ה-`.md` וה-`.html` הם קבצי עבודה ונשארים מקומית - אין להעלות אותם.

⚠️ **שינוי מ-28.7.2026.** הכלל הקודם היה ששלושתם (`md`+`html`+`pdf`) עולים יחד לאותה תיקייה. הילה ביקשה לצמצם: "אני רוצה בדרייב רק את ה-pdf, בהקשר של כתיבת טקסט לא בהקשר של יצירת תמונות". הסיבה - Drive לא מרנדר HTML אף פעם, ולכן ה-PDF הוא הגרסה היחידה שבאמת נצפית, ושני האחרים היו רעש. **זה חל על תוצרי טקסט בלבד; תוצרים גרפיים לא הושפעו.**

## דרישות

Google Chrome מותקן ב-`/Applications/Google Chrome.app` (סטנדרטי ברוב ההתקנות). אין תלות נוספת - לא Node, לא Python packages, לא מפתחות API.

## פקודה

```bash
${CLAUDE_SKILL_DIR}/scripts/render_pdf.sh <input.html> [output.pdf]
```

אם לא סופק `output.pdf`, נשמר לצד קובץ הקלט עם אותו שם ו-`.pdf` (למשל `newsletter.html` → `newsletter.pdf`). תמונות עם נתיב יחסי (למשל `../merav/outputs/...`) מתרנדרות נכון, כי הקובץ נטען דרך `file://` מהמיקום המקורי שלו.

## דוגמת שימוש טיפוסית (לפני העלאה ל-Drive)

```bash
${CLAUDE_SKILL_DIR}/scripts/render_pdf.sh output/2026-07-28-newsletter-clear-offer.html
# יוצר output/2026-07-28-newsletter-clear-offer.pdf
python3 ${CLAUDE_SKILL_DIR}/../drive-upload/scripts/drive_upload.py upload \
  --file output/2026-07-28-newsletter-clear-offer.pdf --parent <folder_id>
```

## ולידציה ומקרי קצה

- **Chrome לא מותקן** - הסקריפט מחזיר שגיאת JSON ברורה במקום ליפול בשקט.
- **פיצול עמודים באמצע משפט** - עיצובי הניוזלטר בנויים לגלילה רציפה (מסך אחד ארוך), ולא ל-A4 מחולק לעמודים - Chrome print-to-pdf מפצל אוטומטית לפי גודל עמוד סטנדרטי, כך שמשפט עשוי להיחתך בין עמוד לעמוד. זה קביל לתצוגה מקדימה מהירה (עדיין קריא לגמרי בגלילה), לא נועד להיות PDF "מוכן להדפסה" מוקפד.
- **PDF כבד יחסית** (כמה MB) - כי התמונות המוטמעות בניוזלטר נשמרות ברזולוציה המקורית שלהן. לא בעיה לצורך תצוגה מקדימה בדרייב.

## תחזוקה

אם בעתיד יידרש רינדור בלי חלוקת עמודים (עמוד PDF אחד רציף בגובה תוכן העמוד) - זה ידרוש dependency נוסף (Playwright/Puppeteer עם API לקביעת גודל עמוד דינמי), לא ניתן דרך ה-CLI הפשוט של Chrome headless. לא מומש כרגע כי לא נדרש בפועל.
