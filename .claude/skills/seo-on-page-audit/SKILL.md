# seo-on-page-audit — ביקורת On-Page

## מטרה והיקף

ביקורת שיטתית של תוכן קיים (טיוטה של נגה, או דף חי) מול שמונה קריטריונים: אופטימיזציית מילות מפתח, כיסוי סמנטי, קריאות, מטא-דאטה, היררכיית כותרות, EEAT, אופטימיזציית תמונות, וקישור פנימי. הפלט הוא רשימת שיפורים **מתועדפת** (לא כל הממצאים באותה חשיבות) — לא חסימה ולא דרישה לשכתוב אוטומטי, בדיוק כמו כל שאר עבודת דני.

## מתי להשתמש

- שלב ב' של דני (סקירה אחרי שנגה כותבת) — מחליף/מרחיב את הבדיקה הידנית שהייתה קיימת.
- ביקורת עצמאית על דף שכבר חי באתר (למשל "תבדוק אם המאמר הזה עדיין תקין SEO-ית").

## קלט נדרש

| שדה | חובה/רשות |
|---|---|
| טקסט המאמר (`.md` מקומי, או URL חי דרך `WebFetch`) | חובה |
| מילת מפתח ראשית/משניות יעד | חובה (מהבריף המקדים, אם קיים) |
| רשימת ישויות/מונחים סמנטיים (מ-`seo-keyword-research`) | מומלץ |

## תהליך עבודה

1. **קריאות — הרץ את הסקריפט, אל תעריך ידנית**:
   ```bash
   python3 ${CLAUDE_SKILL_DIR}/scripts/readability_he.py <path-to-draft.md>
   ```
   מחזיר JSON עם `long_sentence_pct`, `passive_pct`, ורשימת המשפטים הבעייתיים בפועל (`long_sentences`, `passive_sentences`) — צטט 1-2 דוגמאות קונקרטיות בדוח, לא רק את האחוז. יעד Yoast: עד 25% משפטים ארוכים, עד 10% קול פסיבי.
2. **אופטימיזציית מילות מפתח** — האם מילת המפתח הראשית מופיעה בכותרת, ב-100 המילים הראשונות, ולאורך הטקסט בצפיפות טבעית (לא keyword stuffing — יותר מדי חזרות בצפיפות גבוהה זו בעיה, לא הישג).
3. **כיסוי סמנטי** — השווה מול רשימת הישויות/מונחים מ-`seo-keyword-research` (אם קיימת): כמה מהם מופיעים בפועל בטקסט. חוסר כיסוי של רוב הישויות הוא איתות לתוכן רדוד יחסית למצופה.
4. **מטא-דאטה** — יש כותרת SEO/מטא תיאור/slug (ראה `seo-content-brief`)? האם באורך הנכון?
5. **היררכיית כותרות** — יש H1 יחיד, וה-H2/H3 בסדר לוגי בלי לדלג רמות (H2 ואז ישר H4 למשל)?
6. **EEAT** (Experience, Expertise, Authoritativeness, Trustworthiness) — האם יש סימני ניסיון/מומחיות אמיתיים (דוגמאות מהשטח, לא רק תיאוריה כללית), האם מקורות/נתונים מצוטטים מקושרים, האם יש פרטי מחבר/"אודות" נגישים באתר.
7. **אופטימיזציית תמונות** — לכל `{{IMAGE_NEEDED}}`/תמונה קיימת יש alt-text מתוכנן? שמות קבצים תיאוריים (לא `IMG_1234.jpg`)?
8. **קישור פנימי** — צפיפות סבירה (לא אפס קישורים, גם לא הצפה), אנקור-טקסט תיאורי (לא "לחצו כאן").

## פורמט פלט

```markdown
## ביקורת On-Page: <שם/URL>

**קריאות** (מהסקריפט): X% משפטים ארוכים (יעד ≤25%) | Y% קול פסיבי (יעד ≤10%)
- דוגמת משפט ארוך: "..."
- דוגמת משפט פסיבי: "..."

**ממצאים מתועדפים**:
| עדיפות | ממצא | המלצה |
|---|---|---|
| גבוהה | ... | ... |
| בינונית | ... | ... |
| נמוכה | ... | ... |

**כיסוי סמנטי**: X/Y ישויות רלוונטיות מכוסות בטקסט
**EEAT**: הערות קצרות
```

## ולידציה ומקרי קצה

- **הסקריפט מחזיר `total_sentences: 0`** — כנראה שהקובץ כולל רק כותרות/בולטים/טבלאות בלי פרוזה רציפה; ציין זאת, אל תדווח "100% קריאות" כאילו נבדק בהצלחה.
- **הטקסט מכיל קוד/ציטוטים ארוכים** — הסקריפט כבר מדלג על code blocks; אם יש עדיין עיוות בתוצאה (למשל ציטוט ארוך שנספר כמשפט אחד ענק), ציין זאת ידנית בדוח.
- **אין רשימת ישויות מ-`seo-keyword-research`** — דלג על סעיף כיסוי סמנטי מלא, ציין שהוא לא נבדק, אל תמציא ישויות.
- **keyword stuffing** — אם מילת המפתח מופיעה בתדירות חריגה (הרבה יותר ממה שנשמע טבעי בקריאה), זו ממצא בעדיפות גבוהה, לא ניטרלי.

## שילוב עם סקילים אחרים

צורך פלט מ-`seo-keyword-research` (ישויות, מילות מפתח) ומ-`seo-content-brief` (הבריף המקורי להשוואה). התוצאה מוזנת חזרה ל-`seo-content-brief` במצב "אחרי כתיבה" כחלק מהערות השיפור.

## תחזוקה

אם מתגלים דפוסי קול פסיבי נפוצים שהסקריפט מפספס (למשל מתוך `passive_sentences` שיוצא ריק כשברור שיש קול פסיבי), הוסיפו את הצורה החסרה ל-`PASSIVE_WORDS` בקובץ `scripts/readability_he.py` — לא לבנות regex גורף על כל מילה שמתחילה ב-"נ" (זה תופס גם שמות תואר כמו "נחמד"/"נמוך" ומייצר false positives).
